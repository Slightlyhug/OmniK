## Interactive public atlas

The [LysPTM-StateDB web atlas](https://slightlyhug.github.io/LysPTM-StateDB/) provides public searches of all 1,039,044 rows in `LysPTM-StateDB-all-resours.tsv` and all 2,363,865 rows in `Perturbation_PTM_data.tsv`. Query by protein/source gene label or by the original study/comparison group; inspect all original columns, filter responses and export matching TSV rows. The browser data preserve source strings, missing values and duplicate records. The website is independent of the internal workbench server and uses this published V1.0 snapshot.

Use the website URL for interactive access and the version DOI for archived data attribution. [Website source and rebuild instructions](https://github.com/Slightlyhug/LysPTM-StateDB) · [Suggested manuscript wording and citation](https://slightlyhug.github.io/LysPTM-StateDB/#downloads).

Per-modification exports preserve the integrated source table's eight-column header and row order. Rows carrying multiple comma-separated PTM codes appear in every relevant per-modification file, so their row counts do not sum to a count of unique sites. The 20 exported PTM categories are broader than the eight model tasks.

## Benchmark conventions

`train.csv`, `val.csv` and `test.csv` contain 1,666,028 / 210,344 / 209,846 site rows respectively. There are 105,682 / 13,652 / 13,439 distinct protein identifiers, with no identifier overlap across splits. All-unknown rows number 398,007 / 60,631 / 60,057. These rows remain part of the published splits.

The columns are `site_id`, `uniprot_id`, `position`, `residue`, `window_sequence`, `ubiquitination`, `sumoylation`, `succinylation`, `methylation`, `crotonylation`, `acetylation`, `hydroxyisobutyrylation`, `lactylation`. Labels are 1 (positive), 0 (assigned negative) and -1 (unknown). The supplied 73-character site window has its target at 1-based index 37. Protein positions are 1-based.

The original table export identified 35 / 3 / 3 rows with sequence quality flags (window length, center, alphabet or target checks); these rows are retained. The Zenodo record does not separately deposit that quality flag table. Validate the sequence/window/structure mapping before rebuilding features. No external sequence or structural clustering audit is implied by these file checks.

## Inputs not deposited in V1.0

GitHub separately bundles **one** [Q00169 FASTA](../demo/inputs/fasta/Q00169.fasta) and matching [AlphaFold v6 PDB](../demo/inputs/pdb/Q00169.pdb), an unlabeled 28-site CSV, and reference predictions for the [complete demo](../demo/README.md). These CC BY 4.0 example files have [recorded provenance and checksums](../demo/inputs/provenance.json); they are not the full benchmark sequence/structure collection.

The file catalogue does not include full-length FASTA sequences, PDB files, ESM-2/ESM-IF1 upstream checkpoints, an ESM feature HDF5, graph stores, sharded model features, a standalone training positional prior, or fitted post-hoc calibration artifacts. Retrieve upstream models through the [README links](../README.md#data-preparation), supply matching sequences and structures, and use the published rebuild scripts. The inference config helper can recover the trained positional bias from the released checkpoint.

A rebuilt feature store is compatible with the model input schema, but numerical reproduction of historical predictions requires the matching historical inputs and preprocessing. Current UniProt/AlphaFold/PDB downloads do not establish that equivalence.
